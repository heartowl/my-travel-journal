旅行手帳｜同步修正、登入記憶、同行者唯讀（待實機測試）

重要：這是候選測試版，尚未在你的 Supabase 專案及 iPhone 上實際驗證。不要先刪除任何裝置的資料。

修改內容
1. 逐筆三方合併：不同紀錄的新增、修改、刪除可合併；同筆不同欄位可合併；同欄位衝突停止。
2. 記住登入：瀏覽器 localStorage 儲存 Publishable Key 和 Supabase 工作階段（含 refresh token）；不保存明文密碼。工作階段失效時重新登入。
3. 同行者唯讀：使用 256 位元隨機連結憑證，資料庫 RPC 僅返回指定旅程資料；同行者不需管理者帳密，不能呼叫修改功能。建立新連結會使舊連結失效，可手動撤銷。

重要安全注意
- 同行者連結具有讀取權限，任何拿到連結的人都可查看該旅程的資料，包括備註、花費、訂位連結。請勿公開轉貼。
- 分享頁顯示雲端最後一次同步的內容，非背景即時同步。主人需先在 App 按「檢查並同步」。
- 瀏覽器儲存 refresh token 是維持登入的標準取捨；共用電腦請登出，避免不信任的瀏覽器擴充功能。
- SQL 是新增資料表及 RPC 函式，不會刪除現有 trips/items/preps/packing。

建議安全測試順序
A. 在手機及電腦各匯出完整 JSON 備份，並保留不動。
B. 電腦在 Supabase SQL Editor 執行 SETUP-READONLY-SHARE.sql；檢查沒有錯誤。
C. 將 ZIP 解壓後的專案檔案更新到 GitHub（不要上傳 ZIP 本身）。
D. 先在電腦開啟旅行手帳；登入、重新整理，確認能自動恢復登入。
E. 確認電腦與雲端筆數差異的同步提示後，才決定是否合併。若提示衝突，停止並回報。
F. 同步確認後再建立同行者唯讀連結；先自己在無痕視窗測試，確認無編輯功能，最後才發給同行者。

不要將 Supabase secret/service_role key、密碼放進網頁或傳給同行者。僅 Publishable Key 可以用於前端。
